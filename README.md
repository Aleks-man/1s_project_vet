# Вектор учета

Сайт-каталог программ и услуг 1С для бизнеса в Симферополе, Севастополе и Крыму. Проект содержит главную страницу, каталог решений, отдельные карточки продуктов, описание услуг и контакты.

Приложение построено на React и TypeScript. Во время production-сборки страницы заранее рендерятся в HTML: это ускоряет первую загрузку и позволяет сформировать индивидуальные SEO-метаданные для каждого маршрута.

## Стек

- React 19;
- TypeScript;
- React Router;
- Vite;
- серверный рендеринг React для статического пререндеринга;
- ESLint.

Отдельного backend-сервиса и базы данных в репозитории нет. Форма заказа звонка открывает почтовый клиент пользователя через ссылку `mailto:`.

## Быстрый старт

Понадобятся Node.js и npm.

```bash
npm install
npm run dev
```

После запуска Vite выведет локальный адрес приложения, обычно `http://localhost:5173`.

## Команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Запустить сервер разработки с горячим обновлением |
| `npm run build` | Проверить TypeScript, собрать клиент и SSR-бандл, затем пререндерить страницы в `dist/` |
| `npm run lint` | Проверить исходный код ESLint |
| `npm run preview` | Локально открыть готовую production-сборку |
| `npm run build:client` | Собрать только клиентскую часть |
| `npm run build:ssr` | Собрать временный SSR-бандл для пререндеринга |
| `npm run prerender` | Сгенерировать HTML страниц на основе уже собранных client- и SSR-бандлов |

Для полной проверки перед публикацией:

```bash
npm run lint
npm run build
npm run preview
```

## Страницы

- `/` — главная страница;
- `/catalog` — каталог с фильтрацией по категориям;
- `/catalog/:slug` — подробная страница продукта;
- `/services` — услуги по подбору, запуску и сопровождению 1С;
- `/contacts` — контакты и способы связи.

Список страниц для статической генерации формируется в `src/data/seo.ts`. Карточки продуктов добавляются в него автоматически из `src/data/products.ts`.

## Структура проекта

```text
src/
├── components/       переиспользуемые компоненты интерфейса
├── data/             каталог, контакты и SEO-настройки
├── pages/            страницы приложения
├── styles/           стили отдельных разделов
├── App.tsx           маршрутизация и общая оболочка
├── entry-server.tsx  точка входа статического рендеринга
└── main.tsx          клиентская точка входа и гидратация
public/                изображения, иконки, robots.txt и sitemap.xml
scripts/prerender.mjs  генерация HTML для всех маршрутов
dist/                  результат production-сборки
```

## Где менять данные

### Контакты и тексты главной страницы

Название, телефон, почта, ссылки на мессенджеры, преимущества, отрасли и этапы работ находятся в `src/data/site.ts`.

### Каталог

Продукты и категории описаны в `src/data/products.ts`. Для новой карточки нужно указать уникальный `slug`, категорию, цену, краткое и подробное описание и, при необходимости, изображение.

Изображения коробок хранятся в `public/products/`. Требования к ним и перечень текущих файлов описаны в `public/products/README.md`.

### SEO

Заголовки, описания, canonical URL и перечень пререндеримых маршрутов настраиваются в `src/data/seo.ts`. Базовые метатеги и JSON-LD для шаблона находятся в `index.html`.

После смены домена также нужно обновить `public/sitemap.xml` и проверить `public/robots.txt`.

## Как работает сборка

`npm run build` выполняет три шага:

1. TypeScript проверяет проект, а Vite собирает клиентские файлы.
2. Vite создает SSR-бандл из `src/entry-server.tsx`.
3. `scripts/prerender.mjs` рендерит каждый маршрут, подставляет SEO-метаданные и записывает готовые HTML-файлы в `dist/`.

Временная папка `dist/server/` после пререндеринга удаляется. Для публикации нужен только итоговый каталог `dist/`.

## Публикация

Проект можно разместить на любом статическом хостинге. Команда сборки — `npm run build`, публикуемая директория — `dist`.

Хостинг должен отдавать сгенерированные `index.html` из вложенных каталогов, например `/catalog/1c-buhgalteriya-prof/index.html`. Если платформа нормализует URL или обслуживает маршруты иначе, настройте поддержку SPA fallback на корневой `index.html`.

## Перед production-релизом

В проекте пока есть демонстрационные значения. Перед публикацией обязательно:

- заменить название компании, телефон, email и ссылки на мессенджеры в `src/data/site.ts`;
- заменить `https://example.ru` в `src/data/seo.ts`, `index.html`, `public/sitemap.xml` и `public/robots.txt` на рабочий домен;
- актуализировать цены и описания продуктов;
- проверить права на изображения из `public/products/`;
- решить, достаточно ли отправки заявок через `mailto:`. Для надежного приема заявок потребуется подключить API, CRM или внешний сервис форм;
- проверить юридические тексты, реквизиты, политику обработки персональных данных и согласие пользователя, если форма будет отправлять данные на сервер;
- выполнить `npm run lint` и `npm run build`, затем вручную проверить все страницы и ссылки.

## Ограничения текущей версии

- данные каталога хранятся непосредственно в исходном коде;
- административной панели нет;
- форма не отправляет данные на сервер;
- автоматические тесты пока не настроены.
